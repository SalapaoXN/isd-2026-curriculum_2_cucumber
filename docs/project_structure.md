# Project Structure

This document makes the current repository layout explicit so cleanup work
does not accidentally change runtime behavior.

## Architecture overview

The system is a staged curriculum pipeline followed by a retrieval/QA layer:

1. OCR reads program images into text artifacts.
2. Extraction and merging organize OCR text into structured curriculum records.
3. LLM correction fixes spelling/OCR text in bounded batches.
4. Evaluation compares corrected output against ground truth.
5. `rag.build_index` builds a deterministic runtime SQLite database.
6. `ask.py` answers questions through `rag.qa` using that runtime database.

## Data flow

```text
source/OCR
  -> outputs/
  -> outputs/llm corrected corpus
  -> rag.build_index
  -> cucumber_outputs/runtime/curriculum.db
  -> ask.py / rag.qa
```

More concretely:

```text
inputs/<program>/
  -> python ocr.py
  -> outputs/ocr/

outputs/ocr/
  -> python prepare_data.py
  -> outputs/extracted/
  -> outputs/consolidated/

outputs/consolidated/**/full/merged_*_full.json
  -> python llm_spell_corrector.py
  -> outputs/llm/*_corrected.json

outputs/llm/*_corrected.json
  -> python -m rag.build_index
  -> cucumber_outputs/runtime/curriculum.db
  -> python ask.py
```

## Directory ownership

| Path | Owner / role |
|---|---|
| `ask.py` | Production user entrypoint for QA |
| Root CLI scripts listed below | Intentional CLI/library compatibility surface |
| `config.py` | Root environment configuration (`GEMINI_API_KEY` via `.env`) |
| `rag/` | Production curriculum QA/RAG implementation |
| `src/` | OCR / extraction implementation internals |
| `scripts/` | Maintenance, evaluation, validation, report-generation, and developer tools |
| `outputs/` | OCR/extraction pipeline artifacts; `outputs/llm` is the corrected corpus consumed by RAG index building |
| `cucumber_outputs/` | RAG-generated/runtime artifacts; runtime DB lives at `cucumber_outputs/runtime/curriculum.db` |
| `ground_truth/` | Evaluation/reference datasets |
| `reports/` | Generated or curated evaluation/audit reports |
| `submission/` | Frozen/historical submission package |
| `docs/` | Architecture and project documentation |
| `tests/` | Regression/unit tests |
| `inputs/` | Local source images, normally untracked |

## Artifact distinctions

- **Source data:** `inputs/` images and generated `outputs/` artifacts.
  `outputs/` can generally be regenerated by rerunning pipeline stages.
- **Ground truth:** `ground_truth/` reference datasets used for evaluation.
  These are inputs to evaluation, not pipeline outputs.
- **Runtime artifacts:** `cucumber_outputs/runtime/curriculum.db`, generated
  deterministically from `outputs/llm/*_corrected.json`.
- **Reports:** `reports/` evaluation/audit outputs.
- **Submission artifacts:** `submission/` is a frozen/historical submission
  package. It must not be treated as synchronized runtime data and is not a
  normal input to the runtime pipeline.

## Root Python files are intentional

The following files intentionally remain root-level:

- `ask.py`
- `ocr.py`
- `prepare_data.py`
- `llm_spell_corrector.py`
- `merge_consecutive.py`
- `extract.py`
- `extract_rules.py`
- `evaluate.py`
- `evaluate_curriculum_layers.py`
- `config.py`

They are CLI/library compatibility surfaces, not accidental clutter.
Current CLI commands, imports, tests, subprocess calls, and file-relative
paths depend on that contract. For example, tests import these modules by
their root names, `prepare_data.py` invokes `extract.py` by filename, and
several scripts resolve repository paths relative to their own location.

## Do not move casually

Do not relocate the following without a coordinated compatibility plan:

- **Root CLIs:** moving them changes documented `python <script>.py`
  commands, root module imports, subprocess targets, and file-relative
  path resolution.
- **`rag/`:** production QA path used by `ask.py`, index building,
  evaluation tooling, and tests.
- **`src/`:** OCR/extraction internals imported by root pipeline scripts
  and tests.
- **`outputs/`:** active pipeline artifact root referenced by code,
  documentation, tests, and downstream RAG indexing.
- **`cucumber_outputs/`:** runtime artifact boundary; the runtime database
  path is enforced in code.
- **`submission/`:** frozen/historical package; do not synchronize it with
  runtime data or rewrite paths/filenames preserved there as evidence.
